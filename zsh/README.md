# ZSH Configuration

## Highlights
- **Oh-My-Zsh**: Built on the popular framework.
- **Custom Functions**: Powerful utilities like `explain` (man page AI-like summary) and `cheat`.
- **Auto-Jump**: `j` command to fly between directories.
- **Fast startup**: tool completions are cached to `~/.zsh.d` and `nvm` is loaded on
  first use, keeping a warm interactive start around 190ms.

## Structure

`zshrc` is the only file symlinked into `$HOME`; everything else is sourced from it.
The order is deliberate:

| # | File | Why here |
| :--- | :--- | :--- |
| 1 | `zshrc` | `typeset -gU path fpath`, `export PATH`, `fpath` setup - before anything appends |
| 2 | `env.zsh` | environment and PATH; tools must be resolvable by steps 3+ |
| 3 | `completion-cache.zsh` | writes `$ZSH_COMPCACHE/_<tool>`; must precede `compinit` |
| 4 | `omzsh.zsh` | oh-my-zsh, which runs the one and only `compinit` |
| 5 | `config.zsh` | options, vi mode, key bindings |
| 6 | `alias.zsh` | command shortcuts, and sources `~/.kubectl_aliases` if present |
| 7 | `function.zsh` | advanced shell functions |
| 8 | `completion.zsh` | `compdef`/`bashcompinit` wiring that needs `compinit` to have run |
| 9 | `man.zsh` | colored man pages |
| 10 | `theme.zsh` | generated by `make dark` / `make light`, gitignored |

Two rules keep this working:

- **Nothing before step 4 may bind keys or wrap a ZLE widget.** `zsh-syntax-highlighting`
  must be the last plugin loaded, otherwise it does not wrap widgets added after it.
- **Anything that adds to `fpath` must run before step 4.** `compinit` scans `fpath`
  once; a directory added afterwards is invisible until the next login.

### PATH

PATH is built through the `path` array with the `(N-/)` glob qualifier, so entries
that are not real directories are dropped silently and symlinked directories (`/bin`
on a usrmerge system) are kept. `typeset -gU path` makes it duplicate-free, so a
nested shell - a tmux pane, `zsh` inside `zsh` - inherits a stable PATH instead of
re-appending the whole set.

`export PATH` in `zshrc` is load-bearing. `pyenv init` pipes `$PATH` through
`bash --norc -ec`; if PATH is not in the environment that helper sees an empty value
and hands back bash's compiled-in default, silently dropping every earlier entry.

### Completion cache

`completion-cache.zsh` runs `<tool> completion zsh` for kubectl, helm, eksctl, gh,
minikube, k3s and awless, and stores the output as `~/.zsh.d/_<tool>`. Those
generators emit `#compdef <tool>` as their first line, so the file is directly
autoloadable and costs nothing at startup. A cache entry is regenerated only when
the tool's binary is newer than it, and the stale `.zcompdump` is removed when any
entry changes. Delete `~/.zsh.d` to force a full rebuild.

Completions that cannot be cached this way - aws, terraform, packer, which use
bash's `complete -C` - are wired up in `completion.zsh` behind a one-shot
`bashcompinit`.

## Custom Tools
Run these from your terminal:
- `explain <command>`: Queries `mankier.com` to explain a CLI command.
- `cheat <command>`: Queries `cheat.sh` for examples.
- `mkdircd <dir>`: Make a directory and enter it immediately.

## Alias Cheat Sheet

Git shortcuts come from oh-my-zsh's `git` plugin, not from `alias.zsh` — so it is `gst`
for `git status`, `gco`, `gd`, and so on. Run `alias | grep '^g'` for the full list.

| Alias | Command |
| :--- | :--- |
| `vim` | `nvim` (only when nvim is installed) |
| `c` | `clear` |
| `l` | `eza -lahF`, falling back to `exa -lahF`, then `ls -lAhF` |
| `config` | `/usr/bin/git --git-dir=$HOME/.dotfiles/ --work-tree=$HOME` |

`config` targets a **bare** repo at `~/.dotfiles` tracking `$HOME` directly — a different
layout from this checkout, which lives at `~/dotfiles` and uses symlinks (`make init`).
It is inert unless you have set that bare repo up yourself; the same `--git-dir` backs
`make status` / `make diff` / `make add` / `make commit` / `make ls`.

`k` is **not** an alias. `~/.kubectl_aliases`, if installed, defines a `k` alias, so
`function.zsh:36-40` `unalias`es it and defines a function instead, which echoes
`+ kubectl <args>` to stderr before running. `completion.zsh:11` then restores completion
with `compdef k=kubectl` — a function needs that, whereas zsh follows an alias on its own.

## Optional tools

The config degrades cleanly when these are missing, but they are worth installing:

- [`eza`](https://github.com/eza-community/eza) - `l` uses it when present, then tries
  `exa` (its predecessor), and falls back to plain `ls -lAhF` otherwise.
- [`lf`](https://github.com/gokcehan/lf) - enables the `lfcd` function and its
  `Ctrl-O` binding, which is left unbound when `lf` is absent.
